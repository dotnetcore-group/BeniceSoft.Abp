# 声明式能力

缓存、分布式锁、限流、操作日志通过 ABP 动态代理拦截。

- Host 依赖 `AbpAutofacModule`。
- 方法为 `public virtual`，经注入的接口或类调用。类内部直接调用不拦截。
- 对应模块已 `DependsOn`。

## 缓存

模块：`BeniceSoftAbpCachingMessagePackModule` 或 `BeniceSoftAbpCachingSystemTextJsonModule`。连接：`Redis:Configuration`。

```json
"BeniceSoft": {
  "Caching": {
    "CacheKeyPrefix": "wh",
    "DefaultExpirationSeconds": 300
  }
}
```

```csharp
[Cacheable(ExpirationSeconds = 60, Unless = "__result__ == null")]
public virtual Task<OrderDto?> GetAsync(long id) => Task.FromResult<OrderDto?>(null);
```

可标在类或方法上。

- `Key`：返回 string 的表达式，参数名直接引用，例如 `Key = "\"order:\" + id"`，默认生成器会在表达式结果前拼上配置前缀和方法标识。
- 未设置 `Key` 时，普通无参方法使用方法标识；带参数或泛型的方法使用方法标识加 SHA256 摘要，摘要包含声明类型、参数类型、泛型实参和实际参数值。
- 默认参数按声明顺序使用 `JsonUtils.SerializeBytes` 并传入固定序列化配置，包含公开属性和字段，保留 null、日期精度与集合顺序，忽略 `CancellationToken` 的运行状态。无法序列化的参数需配置 `Key` 或 `KeyGeneratorType`。
- 默认缓存键不会自动包含当前租户、语言或用户权限；结果依赖这些隐含上下文时，业务需显式将其纳入缓存键。
- `KeyGeneratorType`：实现 `ICacheKeyGenerator` 的具体类，无参构造。
- `Condition`：调用前执行。结果为 false 时不读、不写缓存。
- `Unless`：调用后执行。可用 `__result__`。结果为 true 时不写入。
- `ExpirationSeconds` 会再加 30–60 秒随机值。

## 分布式锁

模块：`BeniceSoftAbpDistributedLockModule`。连接：`DistributedLock:ConnectionString`。实现为 Redis Lua，可自动续期。

```csharp
[DistributedLock(ResourceId = "order:{id}", ExpiresMilliseconds = 60_000, AutoRenew = true)]
public virtual Task ShipAsync(long id) => Task.CompletedTask;
```

`ResourceId` 为 SmartFormat，花括号内为参数名。未取到锁抛 `InvalidOperationException`。

`ExpiresMilliseconds` 默认 60000，`WaitMilliseconds` 默认 100，重试间隔默认 25。`AutoRenew` 在过期时间的一半续期。

锁的释放跟随当前 ABP 工作单元：成功时在事务提交后的 `OnCompleted` 回调释放；业务异常、提交失败或完成回调中断时，在 `Disposed` 中清理。方法返回或抛异常时，不提前释放已关联工作单元的锁。没有工作单元时，在方法的 `finally` 中释放。

模块依赖 `AbpUnitOfWorkModule`，使 UOW 拦截器先注册、先建立工作单元。拦截器使用 `IUnitOfWorkManager.Current`，不沿 `Outer` 查找最外层工作单元，保留 `requiresNew` 独立事务边界。同一工作单元内连续或嵌套调用同一资源的加锁方法时复用句柄，已记录为失效的句柄会抛异常。

`AutoRenew` 默认关闭。事务可能超过锁有效期时，应显式设置 `AutoRenew = true`，续期持续到锁句柄释放；关闭续期时，方法执行与事务提交的总耗时必须小于有效期。本地锁状态不能保证 Redis 租约始终有效，进程暂停或网络故障导致的锁丢失不由本次生命周期调整解决。

代码加锁统一使用 `IDistributedLockProvider.TryAcquireAsync(resourceId, expires, wait, interval, autoRenew, cancellationToken)`：成功返回 `IDistributedLockHandle`，等待耗尽仍未取得锁时返回 `null`，取消时抛出 `OperationCanceledException`。通过句柄的 `Dispose` / `DisposeAsync` 释放本次获取的锁，通过 `RenewAsync(expires)` 手动续期，旧句柄不会释放或续期其他请求后来获取的同名锁。

`wait = TimeSpan.Zero` 时仅尝试一轮；`wait > TimeSpan.Zero` 时按 `interval` 重试，间隔必须大于零。Provider 统一管理等待窗口，底层使用 `WaitTime = 0` 且每轮不再隐含重试 5 次。正在进行的 Redis 调用与清理可能超过等待窗口，因此 `wait` 不是严格的端到端耗时上限。直接使用 Redis 扩展的调用仍可通过 `RedisLockProfile.WaitTime` 显式选择等待。

手动获取的句柄不会自动关联工作单元，调用方需要保证持有范围覆盖事务结束。Sample 的 `TestLockManualAsync` 展示了工作单元回调管理句柄的方式；一般 AppService 优先使用特性。

真实 Redis 集成测试位于 `tests/BeniceSoft.Abp.Extensions.DistributedLock.Tests/SampleRedisIntegrationTests.cs`。显式指定 Sample 配置文件后，读取其中的 `DistributedLock:ConnectionString`，使用与模块一致的 DB 0。测试仅创建带随机编号的 `lock:benicesoft:distributed-lock-tests:` 键，结束时逐个清理并检查不存在；事务验证使用独立内存 SQLite，不写入业务数据库。

在框架仓库根目录运行：

```powershell
dotnet build tests/BeniceSoft.Abp.Extensions.DistributedLock.Tests/BeniceSoft.Abp.Extensions.DistributedLock.Tests.csproj -p:GeneratePackageOnBuild=false
$env:BENICESOFT_LOCK_SAMPLE_CONFIG = (Resolve-Path 'samples/BeniceSoft.Abp.Sample.Host/appsettings.json').Path
try {
    dotnet run --project tests/BeniceSoft.Abp.Extensions.DistributedLock.Tests/BeniceSoft.Abp.Extensions.DistributedLock.Tests.csproj --no-build --no-restore
}
finally {
    Remove-Item Env:BENICESOFT_LOCK_SAMPLE_CONFIG
}
```

## 限流

模块：`BeniceSoftAbpRateLimitingModule`，依赖 Redis。配置节 `RateLimiting`。`Enabled` 为 false 时不拦截。

```csharp
[RateLimit(LimitBy = RateLimitBy.UserId, PermitLimit = 5, WindowSeconds = 60)]
public virtual Task SendSmsAsync(string phone) => Task.CompletedTask;

[RateLimit(LimitBy = RateLimitBy.Custom, Key = "{phone}", PermitLimit = 1, WindowSeconds = 60)]
public virtual Task SendOnceAsync(string phone) => Task.CompletedTask;
```

`LimitBy`：`Ip`（默认）、`UserId`、`TenantId`、`Custom`、`Global`。`Key` 仅在 `Custom` 时生效，格式为 SmartFormat。

超限抛 `RateLimitExceededException`（HTTP 429）。`ThrowOnExceeded = false` 时只记日志，方法继续执行。

## 操作日志

分发模块二选一：

- `BeniceSoftAbpOperationLoggingEventBusModule`
- `BeniceSoftAbpOperationLoggingRedisModule`

```csharp
[OperationLog(OperationType = "Ship", BizModule = "Order")]
public virtual Task ShipAsync(long id, OperationLogContext log)
{
    log.BizId = id.ToString();
    log.BizCode = "SO-1";
    log.Remark = "发货";
    return Task.CompletedTask;
}
```

`OperationLogContext` 作为最后一个参数时，其中的 `BizId` 覆盖特性上的 `BizId`。分发失败只记日志。
